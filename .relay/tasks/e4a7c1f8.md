CLI 2.1.233 and Agent SDK 0.3.233 remove the todo/task-tracking tools (`todo_write`, `task_create`, and related) from the default tool surface on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and all newer models. They can be re-enabled via `allowedTools`, the `tools` session option, or the `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` environment variable.

Relay's Tasks sidecar panel renders task-tracking activity from these tools (todo_write events, task creation/updates). On any session using a newer-model default, the Tasks sidecar will silently show nothing — the tools simply won't appear in the stream.

Decision needed (two options):
1. **Re-enable explicitly**: set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` in Claude's spawn environment (the same `env` object built for session starts in `claude-sdk.ts`) so the tools always appear regardless of model. Simple; preserves existing UX at the cost of differing from Claude's own CLI default for newer models.
2. **Graceful degradation**: leave the tools off by default and update the Tasks sidecar to show a contextual note for newer-model sessions ("Task tracking tools are off for this model; enable via settings or ask the model to manage tasks in chat"). More honest about what the model is doing but requires more UI work.

Either way, `ProviderCapabilities` should gain a `todoToolsAvailable` (or similar) flag driven by detected model version so the UI can render correctly without hardcoding model names.

Scope: small–medium (~2–3h). Touch points: `claude-sdk.ts` (spawn env or session args), `ProviderCapabilities`, Tasks sidecar component.

Bucket 0 — priority 1 (deprecation affecting Relay's Tasks panel for all newer-model sessions).

Ref: @anthropic-ai/claude-code CHANGELOG v2.1.233, @anthropic-ai/claude-agent-sdk CHANGELOG v0.3.233
