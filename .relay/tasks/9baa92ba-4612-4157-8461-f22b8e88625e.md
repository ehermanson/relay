The Claude SDK driver adds `result.modelUsage` token counts to `SessionStats` on every result (`handleResult` in `server/core/providers/claude-sdk.ts`). The SDK documents `modelUsage` as a running total for the `query()`: each result carries the total so far, so callers should read the latest one rather than add them up. Relay chats are long-lived streaming sessions, so input/output/cache totals grow roughly quadratically with turns. `accumulateUsage` also adds per-assistant-frame usage into the same counters, which double-counts again.

Fix: pick one source. Either use the frame usage alone, or use the differences between successive `modelUsage` results (a smaller total means a reset after `/clear` or a restart; `thinkingTokens` already works this way, see #56). Then check the context panel totals against a real multi-turn session.
