Agent SDK 0.3.301 adds per-tool permission policies to SDK-type MCP server configs: each tool in an MCP server can now be assigned `always_ask` (always prompt the user) or `always_deny` (always block). Previously only server-level policies existed.

Relay's MCP management (`server/core/mcp-management.ts`) handles adding and configuring MCP servers for Claude sessions via `POST /api/providers/claude/mcp-servers` and project-scoped equivalents. The UI surfaces MCP server config in Global Settings and Project Settings. Currently only server-level config is wired through.

Needed:
1. Extend `mcp-management.ts` to accept and pass per-tool policies (`toolPermissions?: Record<string, 'always_ask' | 'always_deny'>`) when adding or updating an SDK-type MCP server.
2. Update the REST route to accept the new field.
3. Surface it in the MCP server config form (Global Settings → MCP, Project Settings → MCP) — a per-tool permissions table showing each tool with a policy dropdown (default/ask/deny).
4. Validate that the policy field round-trips correctly through `claude mcp add` or the SDK MCP server config.

**ProviderCapabilities / abstraction:** `ProviderCapabilities.mcp.management` — consider adding `supportsPerToolPolicies?: boolean` to gate the per-tool UI. This is Claude-only (no Codex analog for per-tool MCP policies).

**Scope:** Small–medium (~2h). Mostly additive: new optional field on an existing data shape, small UI addition.
