Relay decides which files a chat changed by watching specific tool calls (Claude Edit/Write/NotebookEdit via trackFileChange; Codex fileChange items / patch events). Edits made any other way (Bash sed/scripts, formatters, codegen, git checkout -- file, Codex shell commands) never reach the Files/Review sidecars. A chat can change a dozen files and show no Files or Review sidecar.

## Design

**Attribution by per-turn worktree snapshot** (provider-neutral, in InstanceManager):
- `server/core/worktree-changes.ts`: `captureWorktreeSnapshot(dir)` = HEAD sha + `{relPath → "mtimeMs:size"}` for every path `git status` reports (staged/unstaged/untracked), via `getStatusSummary(dir, { collectPaths: true })` (readOnly, no lock). `diffWorktreeSnapshots(before, after)` → rel paths new or changed in `after`; plus `git diff --name-only beforeHead afterHead` when HEAD moved during the turn (the agent committed). Paths that disappeared are not attributed. Bounded (skip attribution past a path cap).
- Turn start (`dispatchUserMessageLocked`, next to `recordModelSwitchOnDispatch`): capture the baseline before the provider receives the message (await with a short cap; on timeout the turn gets no git attribution, tool tracking still works).
- Turn end (every path that ends a turn, including draining to a queued message): capture `after`, diff, add paths not already in `instance.files` as `FileChange { origin: "worktree", type: untracked ? "added" : "edited", editCount: 1 }`. Apply through the `file_stats` path (like `applyAgentFileList`) — never a `file_list` activity, which would flip the chat to processing. Then the immediate stats pass + `invalidateRepoStatus`.
- Shared checkouts (main space, or several chats in one space worktree): only changes that appeared between this chat's turn start and end are attributed, so one chat doesn't claim another's pre-existing dirt. Concurrent turns in the same checkout may both claim a file — accepted ambiguity.

**Replay**: git-detected files exist in no provider transcript. Persist one `session_events` row per turn (`event: "files_detected"`, payload `{ files }`, only when non-empty). On hydrate/getHistory fold them into `instance.files` (alongside `withAgentFileChanges`); `buildHistoryView` already patches/appends a `file_list` from `instance.files`, so the client needs no new reducer case. `mergeSessionEvents` must not surface `files_detected` as a visible system_event.

**UI**: `hasReviewContent` also true when the chat's worktree is dirty (`useRepoStatus({kind:"instance"})`, already subscribed by the header so no extra wire subscription); the review setup already defaults to `branch` scope when there are no session files. Files panel may show a quiet "detected" hint for `origin === "worktree"`.

**Scope**: managed chats (Claude + Codex) live and on replay. External/terminal chats keep tool-tracked files (no observed turn start) — follow-up. Old chats predating this feature can't be back-filled.

Tests: pure snapshot/diff on a temp repo; InstanceManager end-to-end modelled on test/instance-file-stats.test.js (Bash-style fs write → file_stats with origin worktree; pre-dirty file not attributed; commit during turn attributed; fresh manager over the same DB replays it; works with provider "codex" fake session). CLAUDE.md gets a short section.
