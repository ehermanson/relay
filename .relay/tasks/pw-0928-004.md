Agent SDK 0.3.283 adds a `plugin_errors` array to `SDKSystemMessage`. Each entry has a `path` field identifying which `--plugin-dir` failed to load. Previously these failures were silent — a plugin directory that didn't exist or had a bad manifest would simply be skipped with no user-visible signal.

Relay can surface this in the MCP/plugin status section of the context panel or as a session-startup warning. Users who configure plugin directories in Project Settings would see why a plugin isn't available rather than getting silent capability degradation.

Needed:
1. In `claude-sdk.ts`, read `plugin_errors` from system messages and emit as a new `plugin-error` activity or store on `InstanceInfo.pluginErrors`.
2. Surface the errors in the MCP status panel or context sidecar with a brief "failed to load: `<path>`" label.
3. Consider a `ProviderCapabilities.pluginDirs` flag to gate the UI (bucket-2 capability gate), though the errors can be surfaced without a flag.

Scope: small (~1.5h). Touches: `claude-sdk.ts`, context sidecar or MCP status panel.
