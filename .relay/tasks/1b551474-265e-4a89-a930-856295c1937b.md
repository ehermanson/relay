## Summary

SDK 0.3.284 adds `applied.ultracodeAvailable` and `applied.ultracodeRequested` to `getSettings()` response. These reflect whether the connected CLI supports and has activated ultracode mode.

**Impact on Relay:** CLAUDE.md describes ultracode as offered on "models whose SDK levels include `xhigh`". Using the new `applied.ultracodeAvailable` flag would be more reliable than inferring availability from effort levels — it reflects the actual CLI-side capability after applying the user's config and model constraints.

**What Relay could do:** Read `applied.ultracodeAvailable` during session prewarm or first turn and propagate it to `ProviderCapabilities` so the ultracode toggle in the effort picker hides itself on CLIs or models that don't support it, rather than relying on a static effort-level list.

**Which control this touches:** `ProviderCapabilities.reasoningEffortLevels` / ultracode gate in `claude-sdk.ts`, prewarm path.

**Scope:** Small-medium — add a settings read at prewarm and wire the flag to the capability gate.
