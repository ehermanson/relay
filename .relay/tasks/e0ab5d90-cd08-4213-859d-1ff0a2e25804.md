Agent SDK 0.3.292 adds three new identity fields to background task / delegated-agent events:

- `parent_task_id` on `task_started` events and `background_tasks_changed` entries: the server-assigned id of the parent task that spawned this one.
- `run_id` on background task events: a stable identifier for the agent's current execution run.
- `origin.runId` on task notifications: cross-references a notification back to its originating run.

Relay currently builds its agent tree from the spawning `tool_use` id and `parentAgentId` fields inferred from the Claude transcript. The new `parent_task_id` is a server-side parent pointer that is more reliable when transcript IDs drift (e.g. across compaction boundaries or resumptions). The `run_id` could help `AgentDetail` distinguish successive completions of a resumed agent (the current mechanism uses `endedAt` as the discriminator).

ProviderCapabilities / abstraction: `AgentInfo` type, `mergeAgentInfo` (`agent-info.ts`), `buildAgentTree` (`agents.ts`), Claude SDK driver (`claude-sdk.ts`) task-event handlers.

Needed:
1. Add `parentTaskId?: string` and `runId?: string` to `AgentInfo` (sparse, opt-in — mirrors the existing sparse-upsert contract).
2. In `claude-sdk.ts`, read `parent_task_id` from `task_started` events and `run_id` from background task events; emit them through `agentUpdate`.
3. In `buildAgentTree`, prefer `parentTaskId` over the inferred parent when both are available.
4. Use `runId` as an additional discriminator in the `AgentDetail` query key alongside `endedAt`.

Scope: Small to medium (~2h). Touch points: `types.ts`, `agent-info.ts`, `claude-sdk.ts`, `agents.ts`, `AgentDetail`.
