## Summary

Codex 0.168.0 introduced two changes to how rollout (transcript) files are organized and resolved:

1. **Alternate rollout copies** (#58959): Inherited history now recovers from alternate rollout copies. This implies Codex may generate rollout files at additional or alternate paths when recovering history — paths that Relay's direct file scanning (`codex-discovery.ts`, `codex-transcript.ts`) may not find.

2. **Indexed rollout paths** (#58960): Indexed rollout paths are now preferred when resolving ancestors. This implies Codex maintains an index of rollout paths that it consults to resolve the ancestor chain — Relay does not use such an index and resolves paths by scanning `~/.codex/sessions/`.

**What could break in Relay**: Relay reads Codex rollout files directly in `codex-discovery.ts` (session discovery) and `codex-transcript.ts` (transcript parsing and agent history). If alternate copies are stored under non-standard names or in subdirectories, Relay's current glob pattern `rollout-*-<threadId>.jsonl` may miss them. If the indexed path differs from what a glob scan finds, `readCodexAgentHistory` could resolve the wrong file or find nothing for a given thread.

The failure mode is silent: an external Codex session or child agent history would appear empty or missing rather than erroring, matching the pattern that motivated tracking the 0.153 `item_completed` change.

**Scope**: Inspect Codex PR #58959 and #58960 to understand the actual file layout changes. Update `codex-transcript.ts` and `codex-discovery.ts` if the alternate-copy locations or index format differ from what Relay currently scans. Estimated 2–4h.

**Affects**: `server/core/providers/codex-transcript.ts`, `server/core/providers/codex-discovery.ts`.

Bucket: Breaking/deprecation (0) — rollout file format/layout change that Relay parses directly. Priority 1.
