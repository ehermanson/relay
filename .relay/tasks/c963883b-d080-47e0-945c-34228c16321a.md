Codex 0.165.0 shipped experimental attached thread forks in the app-server API — a way to branch a running thread into a fork without losing the parent. This is Codex's version of session branching, analogous to Claude's `rewind_conversation` primitive (tracked in task a5d82c63).

**Why this passes the chase test:** both providers are independently shipping session-branching primitives. Relay is in the right position to build a shared `ProviderCapabilities.supportsBranching` abstraction that normalises forks/rewinds across providers — a cross-provider feature no single provider team is incentivised to build.

**What Relay could do:** once Codex's API is stable, add a `supportsBranching` capability flag and a shared branch/fork UI control that calls each provider's native primitive. This normalises the feature and avoids two divergent per-provider code paths.

**Next step:** watch for the feature to leave experimental status; at that point assess protocol changes needed in `codex-app-server.ts` and the shared abstraction.

**Scope:** large — design + driver changes for both providers + shared UI.

**Bucket:** new surface (bucket 3), passes the cross-provider normalization chase test. Blocked on Codex API stability (currently experimental). See also task a5d82c63 for the Claude side.
