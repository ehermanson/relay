Both providers now have a plugin/skill catalog model:
- Claude has Skills (`.claude/skills/`, slash-command invocation, marketplace install)
- Codex 0.147.0 added an Agent Plugins catalog (local, personal, workspace, remote install)

Relay currently surfaces Claude skills in the UI (discovered from `.claude.json`, invokable via slash commands). There is no Codex plugin surface.

This is a design task: define a shared `ProviderCapabilities.pluginCatalog` abstraction and a unified Relay UI surface that works for both providers. The abstraction should cover:
- Plugin/skill discovery (what does each provider expose?)
- Install sources (local, marketplace, remote)
- Invocation model (slash commands vs. inline activation)
- Lifecycle (install, enable, disable, uninstall)

Scope: design + research pass (~3–4h). Implementation is a separate task. Would be bucket-2 (near-mechanical) once the abstraction exists.

Bucket 3 (new surface, on-strategy — multi-provider normalization).
