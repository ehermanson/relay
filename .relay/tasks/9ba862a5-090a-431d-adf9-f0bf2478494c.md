Codex 0.163.0 (released 2026-10-15) removes the patched zsh shell in favor of the standard shell executor for Code Mode execution. The patched zsh was the previous execution host; Code Mode `exec` calls now go through a standard shell path.

Relay parses Codex rollout files (`.codex/sessions/*.jsonl`) directly in `codex-transcript.ts` and `codex-discovery.ts`. Code Mode executions in rollouts appear as:
- `custom_tool_call` with `input` containing freeform JavaScript (`codex-tool-activity.ts`)
- v2 `CommandExecution` items with `parsed_cmd` metadata (shell, args, etc.)
- `exec_command` events

If the shell executor change alters the `parsed_cmd` metadata fields (e.g. shell type changes from `"zsh"` to `"sh"` or `"bash"`, or inner command structure changes), the following could break silently:
- `codex-command-label.ts` uses `parsed_cmd` to generate collapsed-row labels for common shell patterns (git, npm, etc.) — wrong metadata means generic fallback labels or incorrect classification
- `exec_command` deduplication by ID in `convertCodexTranscriptEntry` (used in both replay and the watcher)

**Action needed:**
1. Obtain a post-0.163.0 Codex rollout that contains Code Mode execution and compare `parsed_cmd` structure against pre-0.163.0 samples.
2. If `shell` field changed: update the shell matchers in `codex-command-label.ts` and any guards in `codex-tool-activity.ts`.
3. If inner command structure changed: update `codex-transcript.ts` V2 CommandExecution parsing and dedup logic.
4. If no format change: close this task.

**Parsers to check:** `codex-transcript.ts` (`convertCodexTranscriptEntry`, `extractCodexConversationMessage`), `codex-tool-activity.ts`, `codex-command-label.ts`.
