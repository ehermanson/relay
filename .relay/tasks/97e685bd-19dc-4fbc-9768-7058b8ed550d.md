Agent SDK 0.3.304 extends `getContextUsage()` in two ways:

1. **Stable row IDs** — every row in the context-usage response now has a stable ID, enabling incremental diffs and reconciliation between polls instead of rebuilding the display from scratch each call.
2. **Per-server MCP instruction token shares** — when the CLI reports via stdio, the response now includes per-server MCP instruction token counts alongside agent/skill file-path breakdowns.

Relay already calls `getContextUsage()` to populate the Context sidecar panel. The existing `b7c2e4f1` task adds `thinkingTokens` to that panel; this task extends it with MCP cost visibility:

1. Read per-server MCP token entries from the updated `getContextUsage()` response (the new plugin-ID + per-server-share fields).
2. Display MCP server names and their instruction-token share in the Context panel — similar to how skills are broken out.
3. Use the stable row IDs for efficient incremental updates instead of full repaints.

`ProviderCapabilities` or the response itself gates availability (new fields are absent on older CLIs).

Scope: small (~2h). Touch points: `claude-sdk.ts` (context usage reader), context sidecar component, possibly `SessionStats` type if a new field is needed.
