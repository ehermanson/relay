CLI 2.1.224 and Agent SDK 0.3.224 add two new settings:
- `crossSessionInbound`: controls whether messages sent from another session are auto-delivered or held for approval. For full-access (bypassed-permissions) sessions — the default in Relay — the SDK now holds inbound cross-session messages for explicit approval rather than auto-delivering them.
- `dialogExpiry`: controls how long an approval dialog is kept alive before being auto-dismissed.

This behavior change is live in the SDK version range Relay currently targets. Users expecting auto-delivery of cross-session messages in full-access sessions will see approval prompts instead.

Needed:
1. Decide whether Relay should mirror the SDK's new default (hold for approval) or preserve prior auto-deliver behavior by explicitly setting `crossSessionInbound: 'auto'`.
2. Expose `crossSessionInbound` and `dialogExpiry` in project or global settings so users can configure the behavior.
3. Add to `ProviderCapabilities` if these are session-start args (confirm from SDK types).

Scope: small–medium (~2h). Touch points: `claude-sdk.ts` session start args, `ProviderCapabilities`, settings UI.

Bucket 2 — priority 2.

Ref: @anthropic-ai/claude-code CHANGELOG v2.1.224, @anthropic-ai/claude-agent-sdk CHANGELOG v0.3.224
