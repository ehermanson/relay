Agent SDK 0.3.302 (Claude Code 2.1.302) changed the default: `subagent_type: "fork"` sessions now spawn automatically in `claude -p`, Agent SDK, desktop app, and VS Code sessions. Previously only the terminal defaulted to fork subagents; SDK-based sessions required an explicit opt-in or `CLAUDE_CODE_FORK_SUBAGENT=1`. To turn them off: `CLAUDE_CODE_FORK_SUBAGENT=0`.

**Impact on Relay:** Relay manages Claude sessions through the Agent SDK (`claude-sdk.ts`). Now that fork subagents are on by default in SDK sessions, Relay's managed sessions will automatically spawn fork subagents. The CLAUDE.md agent-activity system (AgentStreamState keyed by `parent_tool_use_id ?? "root"`, `supportsAgentActivity` gate, agent cards, Agents sidecar) was designed around terminal sessions that already had fork subagents. Verify that the SDK session path handles fork subagent events identically to the terminal path — specifically:
1. `parent_tool_use_id`-keyed accumulator splitting in `claude-sdk.ts` AgentStreamState
2. `agentId`-attributed output/activity routing through InstanceManager (never touches chat `processing` flag)
3. The Agents sidecar and in-chat cards render correctly for SDK-session fork subagents
4. If any SDK session code path was assuming no fork subagents would arrive, revise it.
5. Consider whether to surface a session-level toggle for `CLAUDE_CODE_FORK_SUBAGENT=0` in per-chat or project settings (analogous to fast-mode or reasoning-effort controls).

**ProviderCapabilities / abstraction:** `claude-sdk.ts` session spawning, `InstanceManager` agent routing, possibly a new `forkSubagentsEnabled` session option in `ProviderCapabilities`.

**Scope:** Investigation first (~30 min to audit the SDK path), then small fix if any gap found.
