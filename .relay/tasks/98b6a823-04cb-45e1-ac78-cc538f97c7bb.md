## Summary

In SDK 0.3.286, omitting `permissionMode` from session-start options changed meaning: it now defers to whatever the user's Claude Code global settings say (which may be auto mode), instead of defaulting to manual approvals. Previously, omitting the field was equivalent to passing `'default'` (manual approvals).

**Impact on Relay:** `claude-sdk.ts` only sets `permissionMode` for three runtime modes (plan/full-access/auto). Any other mode — including the implicit "default/manual" case — currently omits the field and relies on the old behavior. After SDK 0.3.286 that omission uses the user's configured global mode, which may be auto. Sessions that Relay intended to require approval could silently run in full-auto mode.

**Fix:** Audit every session-creation path. Where Relay previously omitted `permissionMode` to mean manual approvals, pass `'default'` explicitly.

**Which control this touches:** `ProviderRuntimeBinding.permissionMode`, `SdkSession` startup options in `claude-sdk.ts` (~line 1249).

**Scope:** Small, surgical — one or two conditional branches in `claude-sdk.ts`.
