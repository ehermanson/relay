Codex 0.162.0 (released 2026-10-08) adds managed git worktree tools for trusted local projects when the worktrees feature is enabled. These tools let a Codex session create, switch, and remove git worktrees from within a session.

Why this matters for Relay: Relay creates and owns git worktrees for Spaces at `~/.relay/worktrees/space-<id>/` and tracks them in SQLite. `sweepOrphanedWorktrees()` removes dirs that are no longer git-tracked. If a Codex session running inside a Relay Space uses the new worktree tools to create or remove worktrees in the same repo, it could corrupt Relay's state: a removed worktree becomes a dangling reference in the `spaces` table; a Codex-created worktree in the worktree base dir could be incorrectly swept on the next startup scan.

Bucket: Breaking/deprecation risk (bucket 0) — potential data-loss path if a user enables the Codex worktree feature while Relay Spaces are active on the same repo.

ProviderCapabilities / abstraction: `SpaceManager` (`space-manager.ts`), `sweepOrphanedWorktrees`, `removeWorktree`.

Needed:
1. Inspect Codex app-server protocol to confirm whether worktree tools are available in app-server mode or only in the TUI.
2. If available in app-server mode: determine whether they operate on the project's own worktree set or a Codex-private one.
3. Harden `sweepOrphanedWorktrees` to not delete worktrees that are valid git worktrees but not Relay-owned (already sweeps only `space-*` name format, but confirm no edge case).
4. Consider adding a runtime warning when both Relay Spaces and Codex worktree feature flags are active in the same project.

Scope: Research + small to medium hardening fix.
