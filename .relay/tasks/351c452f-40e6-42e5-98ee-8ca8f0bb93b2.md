## Summary

In SDK 0.3.287, when a priority message interrupts a mid-flight WebFetch or WebSearch tool call, the `tool_use_result` now arrives as `{ detachedToolCall: true }` instead of the normal text/content result.

**Impact on Relay:** `claude-sdk.ts` and the transcript parser process `tool_use_result` messages. If this new shape is not handled, Relay may display `detachedToolCall: true` as result text, break activity-to-tool matching (CLAUDE.md: "preserve `toolUseId`... parallel tools can finish out of order"), or throw a parse error. The `ActivityMessage.toolUseId` matching logic specifically depends on result shape.

**Fix:** Add a branch in tool-result processing to detect `detachedToolCall: true` and either skip the result or render a "call was interrupted" placeholder.

**Which control this touches:** Tool result handling in `claude-sdk.ts`, `tool-result-preview` rendering.

**Scope:** Small — add a guard in the result processor and a brief UI label.
