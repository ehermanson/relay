## Summary

Claude Agent SDK 0.3.325 (Claude Code 2.1.325) changed `applyFlagSettings()` to **reject calls that would cause Claude Code to discard its settings layer**, throwing an error instead of silently discarding settings as before.

**What changed upstream**: Previously, passing invalid flag combinations to `applyFlagSettings()` silently dropped the settings update. Now the call throws if any value would invalidate the internal settings layer.

**What could break in Relay**: `claude-sdk.ts` calls `applyFlagSettings()` to toggle ultracode mode (`{ ultracode: true }` / `applyFlagSettings({ ultracode: null })`). If the current call site passes a configuration that would now be rejected, those calls will start throwing unhandled errors, breaking session configuration mid-turn.

**Scope**: Inspect every `applyFlagSettings(...)` call in `server/core/providers/claude-sdk.ts`. Verify none pass values that would trigger the new validation. If needed, wrap in try/catch and emit a `SystemEventMessage` warning rather than crashing the session.

**Affects**: `server/core/providers/claude-sdk.ts`, specifically the `applyFlagSettings` path in the ultracode mode handler.

Bucket: Breaking/deprecation (0) — a behavior change in an SDK method Relay directly calls. Priority 1.
