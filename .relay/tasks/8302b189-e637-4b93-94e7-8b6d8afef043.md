## Summary

Claude Code 2.1.323 (Agent SDK 0.3.323) added Code Mode: an experimental, opt-in mode in which Claude writes JavaScript to call its tools rather than making direct tool calls. This mirrors Codex's existing Code Mode, which Relay already handles in `codex-tool-activity.ts`.

**What changed upstream**: Claude Code gained an experimental opt-in `code_mode` session capability. When enabled, tool invocations arrive as `custom_tool_call` entries with freeform JavaScript `input`, similar to Codex Code Mode `exec` calls.

**Why this passes the chase test**: This is a cross-provider normalization opportunity. Relay already has `codex-tool-activity.ts` to handle Codex Code Mode `exec` entries (preserving scripts as `ExecuteCode` activities, extracting bounded text output). Adding equivalent handling for Claude Code Mode would let the same rendering path serve both providers. Without it, Claude Code Mode tool calls would be parsed as unknown tool types and either dropped or rendered incorrectly.

**What Relay needs**:
1. A `ProviderCapabilities.supportsCodeMode?: boolean` flag for Claude (gated on CLI >= 2.1.323).
2. A session-start option to enable it when the user opts in (UI toggle in model options or settings).
3. A handler in `claude-sdk.ts` for the new `custom_tool_call` / code-mode `exec` message shape, feeding into the same `ExecuteCode` activity type that Codex Code Mode uses.

**Cross-provider**: This is the design — reuse the Codex Code Mode path so a user switching between Claude and Codex in the same project sees the same code-execution activity style.

**Scope**: ~4–6h (design for the capability flag, session arg plumbing, and the message handler). The `codex-tool-activity.ts` implementation is the reference.

**Affects**: `server/core/types.ts` (ProviderCapabilities), `server/core/providers/claude-sdk.ts`, `server/core/provider-catalog.ts`.

Bucket: New surface (3) — passes the chase test as cross-provider normalization with Codex Code Mode. Priority 3.
