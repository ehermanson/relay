Claude Code 2.1.283 adds two new managed settings for model access control:
- `availableModelsMatch: { exact: true }` — restricts the model picker to exact version IDs (no alias resolution, no auto-upgrade to the latest in a family).
- `deniedModels: string[]` — blocks specific model IDs from being usable in a session.

These join the existing managed-settings surface that Relay exposes in Project Settings and Global Settings. Enterprise/managed deployments would want these to enforce model governance policies.

Needed:
1. Add `availableModelsMatch` and `deniedModels` to the `managedSettings` type definition in `server/core/types.ts` (or wherever Relay types managed settings).
2. Expose both in the Project Settings and Global Settings UI alongside existing managed-setting fields.
3. Pass through to `buildClaudeSpawnEnv`/SDK session creation; Relay already forwards `managedSettings` verbatim, so the main work is UI exposure and validation.
4. Consider whether `deniedModels` should suppress those IDs from the model picker in Relay's own UI (UX question: Relay's picker vs. the CLI's enforcement).

Scope: small (~2h). Touch points: managed-settings type, settings UI components, maybe model-picker filtering.
