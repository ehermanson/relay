## Summary

Claude Agent SDK 0.3.325 added `archiveSession()` and `unarchiveSession()` methods, plus an `archived` boolean field on results from `listSessions()` and `getSessionInfo()`.

**What changed upstream**: Sessions can now be explicitly archived via the SDK. Archived sessions appear with `archived: true` in listing and info results. This is a provider-managed lifecycle state distinct from "complete" or "stopped."

**What Relay could do**: Relay reads session info and lists sessions via the Claude SDK in `claude-sdk.ts`. The new `archived` field will appear on session info responses and session listings. Two opportunities:

1. **Display archived status**: If a managed session has `archived: true` in its `getSessionInfo()` response, Relay could surface this in the chat's status or provider status so users know the session was archived (by another client, by a scheduled job, etc.).

2. **Archive on mark-done**: When Relay marks a chat done (`setDone`), it could optionally archive the underlying provider session, freeing resources on the provider side. Gated by a `ProviderCapabilities.supportsArchive` flag.

**Cross-provider note**: No Codex equivalent yet. File as a Claude-only bucket-2 for now; if Codex adds `thread/archive`, the abstraction is `ProviderCapabilities.supportsArchive` + a `archiveSession?()` method on `ProviderSession`.

**Scope**: ~2–3h. Add `archived?: boolean` to the session info type, read it in `claude-sdk.ts`, expose via `InstanceInfo.providerArchived`, and optionally surface in the chat status bar. `archiveSession()` itself is optional for this task.

**Affects**: `server/core/providers/claude-sdk.ts`, `server/core/types.ts`.

Bucket: Capability declaration (2) — new SDK API and session field to surface. Priority 2.
