## Summary

SDK 0.3.285 adds `provider_not_allowed` to the `startup_failure_reason` enum and adds `allowedProviders` to the `Settings` type. This fires when an enterprise-managed `allowedProviders` setting blocks the API provider the session tries to use.

**Impact on Relay:** Relay's session startup error handling (InstanceManager + claude-sdk.ts startup path) needs a branch for this new reason code. Without it, a blocked session either silently fails, logs an unhelpful generic error, or crashes the error handler if it exhausts the known enum values.

**Fix:** Add `'provider_not_allowed'` to the startup-failure handler in `claude-sdk.ts` / `instance-manager.ts` and surface it as a human-readable error state in the chat UI (e.g., "This provider is blocked by your organization's policy").

**Which control this touches:** `startup_failure_reason` handling, session error state in the UI, possibly `ProviderCapabilities` if Relay wants to proactively check allowed providers.

**Scope:** Small-medium — error handler branch + UI copy.
