## Summary

Claude Agent SDK 0.3.323 (Claude Code 2.1.323) added a periodic `tool_progress` heartbeat message that fires while a turn is waiting on a long-running `PreToolUse` or `PostToolUse` hook. The message has `tool_name` set to the hook event name, `tool_use_id` starting with `hook-`, and optionally `parent_tool_use_id` naming the blocked tool call.

**What changed upstream**: A new heartbeat message type `tool_progress` now arrives on the SDK event stream while Claude Code's turn is blocked waiting for a hook to respond. This was added so that callers can distinguish "Claude is running a long hook" from "Claude is hung."

**What Relay could do**: Relay processes SDK messages in `claude-sdk.ts` and surfaces activity in the chat. The `tool_progress` message is a new SDK event type that Relay doesn't currently handle. At minimum, Relay needs to silently ignore it (to avoid "unknown message type" noise in logs); better, it can emit a brief `ActivityMessage` ("Waiting for hook…") that disappears once the hook completes, so the chat doesn't look frozen.

**ProviderCapabilities touch point**: None required — this is a new message type to handle, not a new session-start option. Add a handler in `claude-sdk.ts` alongside the existing `tool_use`/`tool_result` handling. If surfacing as activity, the existing `ActivityMessage` type already supports tool-name and tool-use-id.

**Scope**: ~1–2h. Add a case for `tool_progress` in the SDK message handler. Optionally emit a transient activity that the reducer clears on the next `tool_result`.

**Affects**: `server/core/providers/claude-sdk.ts`, possibly `server/core/types.ts` if a new activity subtype is needed.

Bucket: Capability declaration (2) — new SDK message type to handle. Priority 2.
