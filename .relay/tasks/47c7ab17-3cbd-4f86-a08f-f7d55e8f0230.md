Decisions (Eric, 2026-09-30), superseding the Claude-only shape of d781edbc: an **Account** (`Account` in types.ts; helpers in `server/core/accounts.ts`) is a named context ('Work', 'Personal') owning **one login (config dir) per provider it uses**. The default account is implicit: the server's own dir for every installed provider; only its label is stored.

- A provider with **no login** in the active account is **hidden** there (pickers, defaults, creation) — never a fallback to another account's login.
- Reshape now, before shipping: `global_settings.accounts_json` replaces `provider_profiles_json` (migrated on read: one account per legacy profile); chats carry `InstanceInfo.accountId` (`managed_sessions.account_id`) alongside the `configDir` binding; terminal chats resolve by (provider, transcript root); `Project.accountIds` are account ids; the query/body param is `accountId` everywhere (no `profileId`).
- Capability `supportsAccountLogins` (Claude: CLAUDE_CONFIG_DIR, Codex: CODEX_HOME) replaces `supportsAccountProfiles`. Codex adopts it in this pass: CODEX_HOME on every spawn, per-home discovery/scan/models/identity.
- API: `GET/POST /api/accounts`, `PATCH/DELETE /api/accounts/:id`, `POST /api/accounts/:id/probe`; `GET /api/providers?accountId=` lists only providers with a login in that account. `/api/providers/:provider/profiles*` is removed.
- UI: Settings gets a top-level **Accounts** section (one card per account, one row per provider login with probed identity; default account renamable). The switcher, filtering and per-account provider state from d781edbc carry over, keyed by account.
- **Single account ⇒ the UI is exactly as before**, apart from the Settings affordance to add an account. New providers (e.g. OpenCode) need a driver first; the account model is provider-agnostic.
