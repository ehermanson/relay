Agent SDK 0.3.280 adds an optional `fireReason` field to the `SDKMessageOrigin` of `task-notification` messages. This explains why a task notification fired — the known value so far is `"worker_restart"`, indicating the background task's worker process was restarted.

Relay parses `task-notification` origins in `agent-messages.ts` to classify them as `agent_update` events (status changes, results). Adding `fireReason` gives Relay two improvements:
1. When `fireReason === "worker_restart"`, Relay can mark the agent as having been interrupted and resumed rather than showing a spurious "completed then restarted" sequence.
2. The `lastActivity` label for that agent can read "Worker restarted" rather than a generic "Received a message."

Needed:
1. Read `fireReason` from `task-notification` origins in `agent-messages.ts` (`classifyUserEnvelope`).
2. Forward it as an optional field on the emitted `agent_update` (`AgentUpdateMessage.raw.fireReason`).
3. In the agents sidecar / agent card, use `fireReason === "worker_restart"` to label the last activity as a restart rather than a generic notification.

Scope: small (~1h). Touch points: `agent-messages.ts`, `AgentUpdateMessage` shape, agent card lastActivity label.
