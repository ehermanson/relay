Codex 0.157.0 enables background daemon auto-start by default. Previously, running `codex` started a foreground process; now Codex may start a background daemon process first and attach to it. This changes what `ps` returns for a Codex session.

Relay's external session discovery (`server/core/providers/codex-discovery.ts`) finds Codex sessions by scanning for `codex` processes with a matching cwd via `ps` + `lsof`. If Codex now always runs a background daemon, Relay might:
1. Discover the daemon process as if it were a user-visible session (false positive).
2. Pair a managed session's PID to the daemon rather than the foreground process (misidentification).
3. Miss sessions whose foreground process was a thin client that quickly exited (false negative).

Needed:
1. Test the new daemon mode: start Codex 0.157.0+ in a known directory, run `ps aux | grep codex`, and observe what process(es) exist and what their cwd is.
2. If the daemon uses a different process name or cwd, update `codex-discovery.ts` to exclude or correctly classify daemon processes.
3. If the daemon/client architecture changes how external sessions should be matched, update the discovery logic and tests.

Scope: small investigation + potential patch (~2h). Touch points: `codex-discovery.ts`, `codex-process.ts` (if it exists), integration test.
