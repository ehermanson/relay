Loading an individual session is noticeably slow. Initial app load taking a few seconds is acceptable, but navigating to a specific session should feel near-instant.

**Investigation scope:**
1. Profile and identify the current bottleneck — is it JSONL parsing, SQLite queries, WebSocket hydration, UI rendering, or a combination?
2. Measure where time is spent: server-side (history fetch, JSONL read/parse) vs client-side (message processing, rendering)
3. Check if we're doing redundant work (re-parsing JSONL that's already been parsed, re-fetching data we already have)

**Potential improvements to evaluate:**
- Pre-fetching: load session data in the background when hovering/navigating near a session, or eagerly fetch recent sessions on app load
- Data storage: cache parsed history in SQLite instead of re-parsing JSONL every time a session is opened
- Faster queries: optimize SQLite access patterns, batch reads, prepared statement reuse
- Incremental loading: show the last N messages immediately, lazy-load older history
- Client-side caching: keep previously-loaded sessions in memory so revisiting is instant

**Approach:**
Start by instrumenting the current flow to identify the actual bottleneck before optimizing. Don't assume — measure first.
