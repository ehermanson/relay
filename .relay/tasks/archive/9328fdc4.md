When an agent turn finishes in a chat that the user is not currently viewing (different chat, different page, or tab not focused), pop a toast notifying them that the chat is ready. Clicking the toast should navigate to that chat.

**Trigger condition:** an instance transitions from running → idle (turn end) AND the user is not actively viewing that chat. "Not viewing" covers: looking at a different chat, on a non-chat page (settings, plans, tasks, etc.), or the browser tab is hidden (`document.visibilityState === 'hidden'`).

**Implementation notes:**
- Detect the running→idle transition client-side by diffing instance status across WS updates (similar pattern to `prevInstanceIdsRef` in `app/src/context/action-toast-context.tsx`).
- Compare against the currently-focused chat ID (available from the router / sidebar nav controller).
- Use `sonner` toasts with the chat name + a click handler that navigates to the chat.
- Consider rate-limiting / coalescing if multiple chats finish in quick succession.
- Optional: also flash `document.title` or favicon when the tab is hidden, since toasts won't be visible.
- Optional follow-up: browser Notification API for true OS-level alerts (requires permission).

**Open questions:**
- Should this fire for every turn end, or only when the user explicitly sent a message and walked away? (Avoid toast spam from agents doing multi-turn tool loops that punctuate at idle moments.)
- Should rate-limit / completion notifications be a separate category from turn-end?
