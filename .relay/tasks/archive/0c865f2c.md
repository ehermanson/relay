Surface provider usage status and rate limits per provider in the UI.

## Implemented (2026-04-04)

### Codex
- Full rate limit bars with `usedPercent`, `windowMinutes`, `resetAt` from `account/rateLimits/read` RPC and live `account/rateLimits/updated` events
- Account info (plan, email) from `account/read`
- Displayed in both sidecar (provider status section) and global settings page
- Shared `RateLimitBar` component with `windowLabel()` helper ("5h window", "Weekly", etc.)

### Claude
- `rate_limit_event` stream events now handled (previously skipped as telemetry)
- Accumulates windows by `rateLimitType` (`five_hour`, `seven_day`, etc.)
- Maps to same `ProviderRateLimitStatus` shape as Codex
- `accountInfo()` SDK call on session init → populates plan, email, org
- Hydration on client reconnect via `ensureProviderGlobalState("claude")` harvesting from active sessions

### Limitations (upstream)
- Claude SDK does not send `utilization` for `allowed` status — only `resetsAt` and window type. Usage percentage only available during `allowed_warning` or `rejected`
- `seven_day` window events only emitted when near/at the weekly limit
- No polling API — data only arrives when a session is active and turns fire
- Rate limit data lost on server restart (no persistence); re-populated after first turn
