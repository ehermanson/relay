Let users grab content from one chat and send it to another chat in the same space, avoiding manual copy-paste between chat tabs.

**Use case:** Chat B reviews code written by chat A. The review produces feedback. User clicks "Send to Chat A" on the review message, and chat A receives the feedback as a new user message (or injected context) so it can act on it.

**Proposed design:**
- Add a "Send to..." action to the message context menu (or a dedicated button on assistant messages)
- Clicking opens a picker showing other chats in the same space
- Selected content is sent to the target chat as a user-attributed message (prepended with context like "[From: Review Chat] Here's the code review feedback:")
- If the target chat is idle, this acts as a new user turn that wakes it up. If busy, it queues as the next user message.
- Support sending: (a) a single message, (b) a selection/range of messages, (c) a summary of the chat so far

**Implementation notes:**
- WS message: `send_to_chat { fromInstanceId, toInstanceId, content, contentType: 'message' | 'summary' }`
- Server-side: inject the content into the target instance's input queue (same mechanism as the user typing and hitting send)
- UI: toast confirmation ("Sent review notes to Chat A"), maybe a backlink in the target chat ("Received from Chat B")

**Key questions:**
- Should "send to" also work across spaces within the same project, or strictly within a space?
- Should we support sending to a chat that doesn't exist yet (i.e., "send to new chat" which creates one)?
- Rich content: if the source message contains code blocks, file references, etc., should those be preserved or flattened to text?
