Turn the current chat debug modal into a larger debug workspace that stays anchored to the real chat context instead of rebuilding a separate environment. Start with a chat-scoped debug surface or nested debug route that reuses the current instance, items, raw history, and actions.

Initial scope:
- Preserve quick chat-local inspection of raw history, processed items, and instance state
- Add UI state presets for common edge cases such as reconnecting, interrupted turn, pending plan, branch-changed, stale external session, queue backlog, approvals, terminal input, MCP elicitation, and provider notices/reroutes
- Add a generic request simulator for Relay-native request shapes (`approval`, `user_input`, `terminal_input`) with category/source, tool, command, files, questions, and description/prompt fields
- Add an instance patch editor for local `InstanceInfo` overrides so banners, header badges, sidecar, and composer states can be previewed without waiting for live provider events
- Add transcript/event injection so synthetic `activity`, `system_event`, `output`, and `error` entries can be rendered against the real chat UI

Follow-on scope:
- Raw provider event paste/replay with a compare view for raw payload -> Relay-normalized event/state -> rendered UI
- Provider-status inspector for normalized live provider state
- Copy/export support that turns demo states or pasted payloads into reusable test fixtures

Design notes:
- Prefer a chat-scoped full-page or nested debug view over a disconnected global route so the workspace can reuse existing chat context and UI composition
- Keep provider-specific protocol details out of Relay shared schema; the debug tools should help inspect provider mapping, not justify leaking provider-native shapes into the contract
- Leave a smaller quick-inspection modal path in place if it still adds value after the larger surface exists

Success criteria:
- A developer can preview and interact with complex chat states without reproducing them live
- The workspace is useful for both protocol integration work and UI regression testing
- It becomes easier to turn observed edge cases into fixtures and automated tests
