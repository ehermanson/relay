Let users select text from an agent message and reply to it inline, building up a composed response from multiple selections.

## Core Flow

1. User highlights text in an agent message
2. A small popover appears near the selection with a text input
3. User types a short reply in the popover, confirms (Enter or button)
4. The selection + reply is captured as a pending reply fragment
5. User repeats for other parts of the message (e.g. answering multiple questions)
6. All fragments populate the composer as blockquoted selections with replies underneath:
   ```
   > Selected agent text here
   My reply to that part

   > Another selected passage
   My reply to this one
   ```
7. User can edit the composed message in the composer before sending

## UX Details

- **Selection popover**: minimal — small text input + confirm. Appears near the selection (above or below). Dismiss on click-away or Escape.
- **Visual feedback**: after replying to a selection, some indication that a fragment was captured (subtle highlight on the quoted region? a badge/count near the composer?)
- **Composer population**: fragments appear in order they were created. User can reorder, edit, or delete in the composer before sending.
- **Keyboard-friendly**: Tab into the popover input after selecting, Enter to confirm, then back to reading the message.

## Prior Art

- Plan mode already has inline comment UX — may share patterns for selection detection and popover positioning
- Similar to email quote-reply or Notion's inline comment flow

## Implementation Considerations

- `window.getSelection()` to detect selected text and anchor position
- Need to handle selection across markdown-rendered content (get plain text, not HTML)
- Popover positioning relative to selection range bounding rect
- State: array of `{ selectedText: string, reply: string }` fragments, managed until flushed to composer
- Formatting as blockquote in composer input (markdown)
- Consider: should this work on user messages too, or only agent messages?
