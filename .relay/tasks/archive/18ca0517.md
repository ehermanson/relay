CLI 2.1.219 adds `mcp_server_errors` to the headless stream-json init event — an array of `--mcp-config` entries that failed config validation and were skipped at startup.

Relay launches Claude sessions in headless mode and processes the stream-json init event in `claude-sdk.ts`. The MCP management UI shows configured and connected servers, but currently has no way to surface servers that failed to start.

Needed:
1. Parse `mcp_server_errors` from the headless init event in `claude-sdk.ts` and include it in the MCP state broadcast.
2. Surface failed servers with their error reason in the MCP panel — either inline on the server row (a red error badge) or as a dedicated "failed to start" section.
3. Coordinate with `ProviderMcpServerStatus` (`failed` state): ensure `mcp_server_errors` entries map correctly to `failed` status.

Scope: small–medium (~2h). Touch points: `claude-sdk.ts` (init handler), MCP state broadcast, MCP panel UI.

Bucket 2 — priority 2.
