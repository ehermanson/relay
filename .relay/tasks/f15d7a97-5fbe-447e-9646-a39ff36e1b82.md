Follow-up to the CLAUDE_CONFIG_DIR fix. Let a machine with several Claude logins (each its own config dir, e.g. ~/.claude personal vs ~/.claude-work enterprise) choose which account a chat runs under, from the Relay UI.

Design:
- Settings → Providers → Claude: an **Accounts** list of labelled config dirs (default ~/.claude plus user-added). Relay probes each via SDK startup() with env.CLAUDE_CONFIG_DIR and shows the discovered identity (email · org · plan) — never a hand-typed label alone.
- Global default account + per-project override in Project Settings (next to default provider/model). Chats inherit at creation; the chat header shows the account beside the model.
- managed_sessions stores the config dir per chat so --resume always uses the dir the transcript lives in; a chat's account is fixed after creation (like its provider).
- providerDirs.claude becomes a list: the startup scan, JSONL watchers, plans and external discovery walk every profile's projects/ root; external sessions are attributed to the profile whose root holds their transcript.
- Model it as a provider capability (supportsAccountProfiles / profile on the session contract), not Claude-only branching — Codex has the same concept via CODEX_HOME even if only Claude ships first.
- Account info caches (models, account, rate limits) in claude-sdk.ts are module-level singletons today; they must become per-profile.
