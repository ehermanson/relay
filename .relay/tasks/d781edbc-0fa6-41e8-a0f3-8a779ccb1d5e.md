Decisions (Eric, 2026-09-25): the account (a provider login = config dir, `ProviderAccountProfile`) is the highest layer of the UI, like browser profiles. A per-browser **active account** decides everything in view; there is no per-chat picker, no global/project 'default account' setting, and no escape hatch. **With a single account registered, nothing in the UI changes.**

- Projects are **scoped** to accounts (`Project.accountIds`); the same directory may be added to several accounts. Adding a project while in account X registers it under X. Deleting a profile removes it from memberships; a project left with none falls back to the default account. Rows with no membership = default account.
- Chats show under the account they are bound to (`InstanceInfo.configDir`, incl. terminal chats); new chats pass the active `profileId` on `create_instance`. A chat's account never changes.
- Provider state follows the active account: model discovery keyed by config dir (lazy per-dir probe, 30-min TTL; `GET /api/provider-models?profileId=`), provider global state (account identity, rate limits, MCP servers) keyed by (provider, configDir) incl. persistence and WS broadcasts, MCP list/add, skills, plans/artifacts all take `profileId`.
- UI: account switcher at the top of the sidebar (and mobile home/drawer) only when >=2 accounts; `useActiveAccount` (localStorage) filters the shared navigation model (sidebar, mini rail, mobile home, dashboard, search). Remove the global 'Use for new chats' radio, the project 'Account' select, and the chat header/context-panel account chip (redundant once views are per account). Project Settings gets an 'Accounts' membership control (>=2 accounts only). Bump the persisted query cache buster (projects shape).
- Deprecated, no longer read/written: `Project.defaultProfileId`, `ProviderDefaults.profileId` (columns stay).
