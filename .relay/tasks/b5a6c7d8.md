Claude Code CLI 2.1.267 adds a `maxEffortLevel` managed setting. This is an operator-configurable cap on the maximum reasoning effort a session is allowed to use — preventing runaway extended-thinking token spend on managed deployments.

Relay exposes `reasoningEffortLevels` in `ProviderCapabilities` and lets users pick a level per session. `maxEffortLevel` is a server-side ceiling on those picks — once set, the UI should clamp the picker's available options to the configured maximum.

Needed:
1. Add `maxEffortLevel?: ReasoningEffort` to `ProviderCapabilities` for the Claude driver.
2. In the Claude driver, detect `maxEffortLevel` from the managed settings and include it in the capabilities broadcast.
3. In the model options UI (reasoning-effort picker), cap the available options at `maxEffortLevel` when present — options above the cap are hidden or disabled.

Scope: small (~1–2h). Touch points: `ProviderCapabilities` type, `claude-sdk.ts` (managed-settings parsing), reasoning-effort picker UI.

Bucket 2 (capability-declaration) — priority 2.
